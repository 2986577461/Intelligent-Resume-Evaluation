# 简历指导工作流

## 需求

主线 A：帮助已有初稿的技术实习/校招求职者识别优先修改的问题；补充 B：围绕实际内容准备面试追问。输出有依据、具体、可执行，不评数字分，不认证经历真实性，不预测录用。

本轮保留外层工具选择、结构化暂存和跨轮恢复，将工具内部四个独立审阅节点及综合调用替换为一次综合分析。**这是架构简化，不是已经证明同质量、更便宜或优于通用 AI 的结论。** 验收标准、合成案例、行为测试与未完成的人工审核见 [A/B 需求与验收](guidance-acceptance.md)。

## 生产流程

```text
用户消息与可选附件
       ↓
外层 Agent：普通问答 / 读原文 / analyze_resume
       ↓ 工具被选择时
校验账号、会话、文件归属（本轮附件优先）
       ↓
本地暂存 / Redis 成功提取缓存 / 重新解析事实
       ↓
结合本轮消息、原文、已确认上下文、当前日期识别投递目标
       ├─ 缺岗位或投递类型 → 保存 waiting → 追问缺项
       └─ 信息充分 → 保存 ready
                          ↓
                   单次综合分析 synthesis
                          ↓
             模型 JSON 流 → 完整条目校验 / 引用回查
                          ↓
             总体判断 → 优先建议 → 关联面试追问
                          ↓
                  确认完整协议 / 保存同一正文
```

`scoring.py`、`build_scoring_graph` 和超时环境变量保留旧名称以兼容入口，内部不算分。首次完整指导正常有3次内部模型调用：提取1、上下文1、综合分析1；复用提取后2次。缺上下文时不执行综合分析。外层路由、可能的读原文、标题生成、OCR 和搜索不计入此数量。重试会增加调用。

前端不强制求职表。岗位和投递类型是完整分析的必要信息，可以从用户消息或明确简历标题取得；JD 可选，不提供也正常分析，不将其视为缺点。用户当前明确目标优先于旧目标和简历意向。仅根据毕业时间推测的类型标记 inferred，仍需确认。

外层 Agent 在用户补充目标时恢复工具；“校招是什么意思”、取消或闲聊不应触发分析。报告后解释某条建议/追问默认普通问答，必要时读原文，不默认重跑。报告是模型判断，用户纠错时应回查原文，不把旧判断当作事实。对话补充不自动改写原文件或历史报告。上述意图识别受真实模型影响，离线接线测试不能证明一定正确。

## 协议与证据

- `Extraction`：稳定的文件事实摘要；综合分析仍拿完整原文，避免把摘要遗漏当成没写。
- `GuidanceContext`：岗位、投递类型、可选 JD；每项有值、source、evidence、inferred。上下文与文件事实分开，改目标不污染提取缓存。
- `Synthesis`：`overview`、0–3条 `actions`、0–5条 `interview_questions`。不强制五模块、匹配等级或最低问题数。
- `ActionItem`：唯一 A1/A2/A3、对象、优先级、动作类型、原文依据、观察与问题、岗位影响、下一步。缺失信息允许空依据，必须谨慎表述；语义是否谨慎仍需人工审阅。
- `InterviewQuestion`：可空 action_id、对象、具体问题、至少一条原文依据、考察点、准备方向。非空关联必须存在；没有需修改问题也可以对清楚的内容追问。
- `Report`：同一份 Synthesis 加投递上下文，供确定性 Markdown 渲染与评测。

结构化请求使用 JSON 对象模式，Schema 放在提示词并由 Pydantic 本地检查，不是模型服务端保证完全符合 Schema。程序回查引用为原文连续片段，仅忽略 NFKC 兼容字形和空白差异，不允许拼接改写。

引用回查只能证明文字存在，不能证明解释忠实、结论公允、信息完整、建议有效，也不能证明经历真实性。总体判断没有强制逐句证据字段；无引用的缺失判断和所有解释都需要语义审核。提取内部仍有 dict 字段，不应宣称全字段事实校验。

## 流式发布与失败

综合分析使用真实 `.stream()`，无整篇生成后切块、sleep 或前端打字队列：

- **总体判断**：增量解码 JSON 字符串，随模型 chunk 展示，正确处理跨 chunk 的转义、Unicode 代理对与空白。不补造引号/括号，不把 JSON 协议发送给用户。此时总体判断可能尚未生成完，完整字符串的 Schema 校验在闭合时进行；这不等于已验证事实与语义。
- **建议**：每条完整、字段和引用校验通过后，高优先级项立即展示，不等整个数组；中低优先级项暂存到数组闭合再排序，保持高→中→低且不回改已展示正文。后续若出现重复 ID，只能拒绝后项并标中断，不能撤回先前已合法发布的一项。
- **追问**：每条完整后检查引用，等建议集合闭合确认关联，再立即发布。支持乱序字段缓冲。
- **前端**：状态随最新服务端事件更新，移除旧500ms排队；正文接收到即追加，没有人工节奏或打字效果。
- **SSE传输**：正文为 `[TEXT]` 加 JSON 字符串，保留真实换行与字面量 `\\n`，正文中的 `[DONE]`/`[STATE]` 不会被当成控制事件。前端兼容旧正文协议，但新后端需要配套新前端，更新后已有页面需刷新。

正文发布前的格式、引用及瞬时网络错误可有限重试；已发布正文后发生断流、截断、结构或引用错误，追加“报告未完成”，不自动重放。结果为 incomplete，不生成成功 report_data。完整成功才加最终免责声明。前端遇到 SSE 错误也保留已展示正文，不整段覆盖。SSE、工具返回与聊天保存保持同一份正文，历史报告无迁移，旧 Markdown 仍正常展示。

## 暂存、缓存与隔离

`GuidanceStore` 在 SQLite `resume_guidance_contexts` 保存当前文件、提取 key、extraction、context、waiting/ready，主键是账号+会话。新附件不会继承另一文件目标。读写均检查文件归属；删除文件外键级联清理，删除会话也清理。

本地状态随应用数据库持久化，没有1小时自动过期。Redis 成功提取 TTL 为1小时，key 为账号/会话/文件/完整文本/提取版本的 SHA-256。版本包括提取协议、提示词、Schema、模型与 API 地址。此次只改分析协议，不改变提取协议，不需要主动失效旧事实缓存。不缓存失败或最终报告。

Redis 连接/读取/写入失败不阻止本地续评。文件与上下文进入备份，应按个人数据保护。外层 Agent SQLite checkpointer 是对话记忆，不等于内部每个节点可持久化断点续跑。

## 文件提取

PDF 用 PyMuPDF `get_text(sort=True)` 按位置重建文本顺序，页间加换行，做 NFKC 兼容归一化。明确标题/求职意向可兜底目标，但不靠技能猜岗位，也不任意选择冲突目标。

位置排序不是通用多栏/表格布局识别，不能凭抽取断行或页数断言原 PDF 版式有问题。历史文件不批量重写，需要重传才能应用新的抽取方式。无文本层的 PDF 和图片仍使用外部 OCR。

## 超时、成本、生产边界

内部模型每次最多8192输出 token，DeepSeek 关闭 thinking。`SCORING_REQUEST_TIMEOUT_SECONDS` 默认60秒，是传输层超时，不是严格节点/全流程 deadline。SDK `max_retries=0`，图节点最多尝试2次（含首次）；格式/引用和瞬时错误可重试，鉴权/权限不重试，已有正文的综合节点不重试。

按 run_id 记录节点尝试、耗时、可获取 usage、提取复用、首段时间和结果。不是完整计费账本：超时/断流可能拿不到 usage，外层路由、标题、OCR 和搜索未统一计费；不能把未知当0。

当前没有全局并发许可、分析配额、请求幂等、可靠断连取消或同会话写冲突控制。并发分析不同文件可能覆盖续评指针；SSE 断开不代表后台停止。标题生成可能延迟 `[DONE]`，不计入工具内部耗时。性能日志不含简历正文，但既有聊天日志和检查点可能含个人信息。

## 验证

离线测试采用合成文本、假模型、Mock HTTP 与临时数据库，不证明真实语义质量、路由选择或用户收益：

```bash
cd ai-backend
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  python -m pytest -v -m 'not llm and not consistency' --disable-socket --allow-unix-socket
```

需安装 `requirements-ci.txt` 中的 pytest-socket 才能使用禁网参数。完整 SDK 环境额外用 `httpx.MockTransport` 验证真实 LangChain→DeepSeek→OpenAI SDK 的 JSON 模式、SSE、超时参数和429重试；SDK 不存在时显式跳过。

真实模型评测会产生费用、外发样本，需要明确授权后执行：

只运行已授权的 S1–S8 合成验收案例及7个单次路由选择（不执行路由工具）：

```bash
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  python -m eval.run_guidance_acceptance --routes --output /tmp/guidance-eval.json
# 可用 --case S7 限定复测，避免整批重复付费
```

合成文本的真实路由→工具→SSE→历史保存（临时 SQLite，禁用标题和 Redis）：

```bash
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  GUIDANCE_STREAM_RESULT=/tmp/guidance-stream.json \
  python -m pytest eval/test_llm_streaming.py -m llm -v
```

本次执行结果和仍未通过的语义问题见 [真实评测记录](guidance-evaluation-results.md)。这些命令会调用真实模型，不要加入默认 CI。下列旧黄金样本测试需额外检查样本授权后再运行：

```bash
python -m pytest -m llm -v
python -m pytest -m consistency -v
```

固定样本的“校招”是测试场景，不是候选人的真实意图。自动评测检查结构、引用、有限实体与重复锚点，不能判断建议是否专业。完整语义与行为验收按 [验收文档](guidance-acceptance.md) 执行。

`eval.benchmark_scoring` 的 hybrid 名称仅保留 CLI 兼容，代表当前工具完整流程；single 是直接 Markdown 提示词路径；legacy 是历史评分路径。它们不是同协议同质量对照，不得用采样宣称单/多节点优劣。未经授权不运行付费基准。

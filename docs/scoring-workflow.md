# 混合评分工作流

保留多维度评分，不以“多 Agent 一定更快”为目标。技能分析必须拿到项目事实和项目分析，避免项目认可某项技术、技能节点却只按自评扣分。

## 生产链路

```text
文件所属校验 → 提取缓存 / 事实提取
                         ↓
                   岗位缺失则询问
                         ↓
            ┌─ 项目分析 → 技能分析 ─┐
            ├─ 经历分析 ──────────┤
            ├─ 学历分析 ──────────┤
            └─ 版式规则计算 ──────┘
                         ↓ 显式 barrier，等待全部成功
                校验 / 加权 / 总分 / 内部评分表
                         ↓
                   跨维度综合分析
                         ↓
               确定性渲染完整分析内容
                         ↓ 首个有效正文
               一次性直接输出评分/优势/风险/追问/总结
```

- `agent/tools.py`：仍使用原聊天工具路径、`return_direct=True` 和已有 SSE 包装；先按用户/会话/文件验证读取权限，再访问缓存。
- `agent/scoring.py`：模型配置、成功提取缓存、缺岗位续评和失败说明。
- `agent/graph.py`：项目→技能依赖、其余分支并行、单节点重试与评分表 barrier。
- `agent/nodes.py`：技能输入含 `skills + position + projects + experiences + project_result + resume_text`。原始项目事实不可用项目分析代替；项目分析不是新的事实。综合分析同时拿到完整原文与实际评估日期，避免把摘要遗漏当作原文没写、用模型训练时间误判项目日期。
- `agent/schema.py`：生产、展示和评测共用类型。分析节点只输出 0–100 的 `raw_score` 和 1–3 条精炼理由；程序计算权重、总分。权重仍为技能10、项目30、经历20、学历35、版式5。
- `agent/telemetry.py`：节点耗时/尝试次数、输入/输出/推理 token、缓存命中、首个正文、整次评分结果与耗时。以 `run_id` 聚合，不记录原文、岗位、模型正文或异常正文。

四个分析 Agent 加一个综合分析调用。首次正常评分 6 次模型调用（提取1 + 分析4 + 综合1），提取命中后 5 次；这不包括外层聊天路由和会话标题。

## 保留综合分析，而不是机械拼接

综合模型仍负责完整的优势、风险与可执行建议、具体面试追问、跨维度总结。只是评分表和算分不再重复生成。输入包含已校验维度结果和提取事实，以便检查维度之间的关联，不仅拼接结论。

综合结果先以 JSON 校验，再将评分表、优势、风险与改进建议、针对性面试追问、总结合并，确定性渲染为一条完整 Markdown 回复。所有分析成功后只推送一次正文，不再先输出“简历评估报告”再追加综合部分；不添加报告标题，免责声明统一放在全文末尾。等待期间仍发送进度状态，内部评分表不会提前展示。综合分析重试不会产生正文；最终失败时只返回失败提示，不展示半份评分内容。工具保留 `return_direct=True`，外层 Agent 不再改写或追加回复，SSE 和历史持久化使用同一份完整内容。

报告不再编造面试成功概率，明确评分不代表实际能力或录用概率。模型结构校验只能证明字段、分值范围等约束，不证明文本语义正确，也不能证明所写经历真实。

## 缓存和兼容

Redis key 为用户/会话/文件、完整文本和版本信息的 SHA-256，不直接暴露个人信息。版本包含提取提示词、协议 Schema、模型名称和配置 API 地址；成功提取保留 1 小时。失败和非法输出不缓存。岗位补充只影响本轮，不污染事实缓存；变更目标岗位可复用事实、重新评分，不缓存最终报告。

权限检查始终早于缓存读取，文件删除后不能绕过文件所属校验读取缓存。Redis 中相应值会在 TTL 后过期，而非随文件删除即时清理。旧 `resume_eval:pending:` 缓存不再读取，任其 TTL 过期；旧聊天报告不重写。

Redis 连接/读写超时各 1 秒且不自动重试；缓存故障或损坏降级为重新提取。无 Redis 的评估仍可工作，但补岗位时可能重复提取。Redis 仍是部署服务，现有 readiness 规则不因此改变。

## 超时、并发和性能边界

评分 DeepSeek 调用显式使用 JSON 对象模式并关闭隐藏 thinking，最多输出4096 token，单次传输请求超时默认60秒，SDK `max_retries=0`。图节点只对格式错误、超时、网络/限流/服务端等瞬时错误重试，最多尝试2次；鉴权/权限错误不重试。非评分聊天和 OCR 不在本轮统一改造。

没有硬性全流程预算、在途任务持久化、全局并发许可或幂等键。多用户重复提交仍可能额外计费，单次传输超时也不是整个工作流的严格墙钟截止。LangGraph 同一轮分支采用 superstep 调度：后继技能节点可能还需等待同轮其他分支完成，不能将理论关键路径当作实测结果。

增加项目→技能依赖，本身会增加串行阶段；传入更多证据也会增加输入 token。首次分析不保证比旧多 Agent 或单 Agent 更快。缓存只缩短重复分析，不解决首次提取耗时。要同时观察质量、首个有效正文时间、完整耗时、成本与失败率，不按 Agent 数量判定优劣。

外层聊天路由另记 `resume_route_timing`，标题阶段另记 `title_timing`；当前标题生成仍可能延迟 SSE `[DONE]`，不混入工具评分耗时。前端展示缓存复用和各维度完成状态，但进度提示不算有效报告正文。

## 离线验证

在 `ai-backend` 下：

```bash
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  python -m pytest -v -m 'not llm and not consistency' --disable-socket --allow-unix-socket
```

`eval/test_scoring_pdf.py` 默认生成合成 PDF，通过真实注册、上传、数据库读取和 `analyze_resume` 工具路径验证缓存、归属和报告。完整模型 SDK 可用时，使用 `httpx.MockTransport` 验证真实 LangChain→DeepSeek→OpenAI SDK 请求的 JSON 模式、thinking、超时和限流重试；仅安装 CI 依赖时显式跳过 SDK 测试。不连接真实 Redis，也不会把指定 PDF 发到网络。

操作者授权的 PDF 可显式指定，不把私有文件放入 CI 或提交评测数据：

```bash
SCORING_TEST_PDF='../test/免费在线简历制作工具-CodeCV简历-2.pdf' \
  python -m pytest eval/test_scoring_pdf.py -v --disable-socket --allow-unix-socket
```

## 付费 PDF 基准

以下命令会加载本地 `.env`，经真实上传/工具路径把 PDF 文本发送给配置的模型服务，产生费用。使用临时账号和临时数据库，不使用真实账号数据库；缓存为测试专用内存实现，**不测真实 Redis 延迟**。报告和模型中间输出可能包含个人信息，只写指定本地目录（目录权限700），不要提交。

```bash
python -m eval.benchmark_scoring --live \
  --pdf '../test/免费在线简历制作工具-CodeCV简历-2.pdf' \
  --output /tmp/resume-scoring-eval \
  --modes legacy hybrid single --legacy-ref 9ae79f6 --warm-cache --repeats 2
```

- `legacy`：从 Git 指定提交临时加载旧工具/图/提示词，不修改工作区。
- `hybrid`：当前真实工具路径；`cold` 不含提取缓存，`warm` 复用同轮提取。
- `single`：同一 PDF、页数、维度和报告目标的一次流式模型调用，作为速度参考，不是质量金标准。
- 三种模式使用同一模型、地址、请求超时、token上限，均关闭 thinking；旧版与单 Agent 的 Markdown 报告不强制 JSON。旧版提取非法不算成功。该受控旧版对照不同于线上仍开启 thinking 的旧配置。
- 工具计时不包含上传、外层聊天路由、标题生成。`cold/warm` 只指应用提取缓存，不控制服务商的 prompt cache。旧版/单 Agent 首个正文是首个 token，新版是完成校验的整份评分表，信息量不同，不是完全相同的 TTFT。
- `summary.json`、逐轮 `*-metrics.json`、`*-report.md` 和私有 `*-model-output.json` 保留测量信息；可增大 repeats/扩展简历集再统计 P50/P95。少数样本不能代表生产尾延迟或分析质量。

当前一次性输出模式中，首个正文要等综合分析完成，因此首个正文时间接近完整分析耗时，不再以内部评分表完成时间计量。下方验证记录为改动前的分阶段输出数据，不代表当前模式的首个正文表现。

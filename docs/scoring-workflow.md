# 简历指导工作流

本产品提供面试官视角的简历阅读意见，不做数字评分。保留 `scoring.py`、`build_scoring_graph` 和超时环境变量的旧名字以兼容工程入口，内部已无权重、总分、学历扣分、固定项目数量或页数扣分。

## 生产流程

```text
校验文件所属账号和会话
       ↓
本地暂存 / Redis 成功提取缓存 / 重新解析事实
       ↓
结合本轮原始消息、简历原文、已确认上下文、实际日期识别投递目标
       ├─ 缺岗位或投递类型 → 保存状态，合并追问缺项，等待用户回答
       └─ 信息充分
              ↓
       项目审阅 ──┐
       经历审阅 ──┴→ 技能关联核验
       教育核对 ───────────┐
                          ↓ 显式 barrier
                  跨模块复核和指导生成
                          ↓
             综合模型 JSON 流 → 分段 Schema / 引用回查
                          ↓
                已完成段落即时转为 Markdown / SSE
                          ↓
                  完整协议确认 → 保存同一份正文
```

先解析，不在上传后强制填写求职表。默认依据岗位名称和投递类型分析，JD 是可选补充，提供时进一步对照具体职责和任职要求；没有 JD 也完成指导，不催要、不作为简历缺点或单独判为“信息不足”的依据。用户本轮明确目标优先于旧目标和简历意向；没有新目标时保留已确认项。PDF 文本先做 Unicode NFKC 兼容归一化，处理“应⽤／实习⽣”等康熙部首字形；分析已有文件时也归一化，不要求重传。提取阶段的岗位会传给上下文识别。程序仅从首行明确岗位标题或靠前的“求职意向”等标签保守提取兜底；标题“AI智能应用开发实习生”同时支持岗位和实习类型，不能因模型遗漏而重复追问。多个冲突目标不自动选择，兜底不覆盖用户已确认目标或撤回指令。

新上传 PDF 使用 PyMuPDF `get_text(sort=True)` 按页面位置重建文本顺序，修复内容流把行内代码、技术标签绘制在正文之后导致的错位；页间显式换行。仍为本地文本提取，不为此新增 OCR 或外部服务调用。位置排序不是完整的多栏、表格、浮动布局识别，不能保证所有 PDF 阅读顺序正确；模型不能仅凭抽取断行就断言视觉排版有误。历史文件保留原提取文本，本轮不批量重写数据库；要应用阅读顺序修复需重新上传，产生新文件和提取缓存，不改写历史报告。

毕业年份与当前日期只能辅助判断阶段，不能机械推导本轮投递类型。只有间接线索时记录 `inferred=true`，仍需追问确认，不把推测当成用户事实。

目标岗位和投递类型分别记录，缺什么问什么；都缺时合并一次询问。用户补充“校招”时，不重问已确认的岗位。聊天路由从服务器接收 `pending_analysis` 元信息，并依赖 Agent 判断用户是否在补充；取消、闲聊不应自动触发续评。这个意图判断仍需真实模型验收，离线状态测试不能证明模型一定选对工具。

首次完整指导通常7次内部模型调用：提取1、上下文1、审阅4、综合1。复用提取后6次。缺上下文时只执行提取和上下文识别，补充后复用提取。外层路由和标题调用不包含在此数量内。

## 中间协议与输出

- `Extraction`：简历事实摘要，不混入用户修改的投递目标。所有审阅仍收到完整原文，避免把漏提取当作未提供。
- `GuidanceContext`：岗位、实习/校招/社招、可选 JD，每项记录值、来源、连续原句、是否推断。
- `AnalystResult`：overview 和按对象保留的 findings。每条发现包含原文证据、判断、岗位影响、建议、动作类型、优先级与可选追问，不输出分数。未提供模块允许没有 findings。
- `Synthesis` / `Report`：总体判断、五个模块（经历、项目、技能、教育、表达一致性）、1–5条优先行动、最多6道针对性追问。行动区分表达调整、补充证据、能力实践和信息确认。渲染器说明本次按岗位分析，或结合用户提供的 JD 分析；不会把 JD 展示为必填缺项。

程序检查引用是否为简历原文连续片段（仅忽略兼容字形、空白差异），非法引用拒绝发布对应段落。它只能证明引用确实存在，**不能证明解释忠实、结论公允或覆盖完整**。模型仍可能用真实引文支持不成立的判断，必须人工复核。

综合节点复核项目/实习/技能一致性、时间、重复经历、教育路径和建议是否可执行。不能仅凭本科两年记录认定专升本；不能凭学校名字猜985/211/双非，不编造企业第一学历门槛；不把常见项目、成熟技术视为低质量。当前没有权威学校资料核实路径；简历自述不等于外部验证。没有访问的链接也不能声称已验证。

正文保持自然的面试官阅读视角，不展示中间 JSON 或隐藏推理。四个审阅节点完成后，综合模型通过 `.stream()` 生成 JSON；`report_stream.py` 只消费真实闭合的字段/数组项，不补造缺失引号或括号。总体判断完成后先展示，各模块完整且引用校验通过后逐段发布，行动与追问继续追加。不是先生成整份报告再模拟打字，也不是逐字符输出；仍需等待审阅完成和首段闭合。

首段发布前的格式/网络等错误仍可有限重试；一旦已有正文，后续断流、截断或校验失败都停止自动重试，追加明确“报告未完成”提示，不泄露服务异常正文，也不重复输出。完整成功才追加全文免责声明。`return_direct=True`、SSE、工具返回和历史保存使用完全相同的正文；不完整报告连同提示也保存在历史中，不作为成功 `report_data`。无 SSE 回调的独立图调用仍可非流式生成同一协议。

## 暂存、恢复与隔离

`agent/guidance_state.py` 将当前文件的提取结果、提取版本 key、已识别上下文、waiting/ready 状态存入 SQLite `resume_guidance_contexts`。每账号/会话保存当前一份文件，新附件优先且不会继承其他文件目标；用户可明确指定旧文件重新分析。表在应用初始化时增量创建，旧聊天内容不重写。

本地状态不仅是 Redis TTL 缓存：它随应用数据库持久化，不自动在一小时后过期。删除文件时外键级联清理；删除会话时显式清理续评状态。备份也会包含解析事实和投递上下文，需按简历数据保护。旧文件是否保留仍遵循现有附件策略，本次未改变。

恢复状态和访问缓存前均校验账号/会话/文件归属；省略文件参数续评时也再次校验。Redis 不可用或过期不丢失本地已确认信息。提取提示词、Schema、模型或配置 API 地址变化会使提取版本失效并重新提取，但保留本轮投递上下文。

Redis 成功提取缓存保留1小时，key 使用账号/会话/文件/完整文本/版本的 SHA-256。失败和非法输出不缓存，不缓存最终报告。旧提取缓存自然过期，不迁移旧评分结果。对话检查点仍由既有 SQLite 保存。

## 超时、成本与边界

结构化调用使用 JSON 对象模式，DeepSeek 关闭隐藏 thinking，单次最多8192输出 token。这个上限为逐对象发现和完整指导预留空间，不代表实际用量。`SCORING_REQUEST_TIMEOUT_SECONDS` 默认60秒，SDK 不重试，图节点对格式、引用和瞬时服务错误最多尝试2次；鉴权/权限错误不重试，正文已经开始发布的综合节点也不再重试。非指导聊天和 OCR 不在本轮统一改造。

增加上下文调用和证据内容会增加潜在成本，不能宣称比评分版更便宜或更快。没有全局并发许可、请求幂等、严格全流程截止或同会话并发冲突控制；同一会话同时分析不同文件可能覆盖当前续评指针，应避免并行提交，后续需要独立处理。

性能日志按 run_id 记录节点时间、尝试数、token、缓存复用、首个正文和完成结果，不记录原文或模型正文。既有聊天日志与检查点可能包含个人信息，仍需保护。标题生成可能延迟 SSE `[DONE]`，不计入工具内部耗时。

## 验证

离线测试使用合成文本和假模型/Mock HTTP，不调用真实服务，也不读取未授权私有简历：

```bash
cd ai-backend
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  python -m pytest -v -m 'not llm and not consistency' --disable-socket --allow-unix-socket
```

覆盖解析先行、PDF 行内代码阅读顺序与页间分隔、标题与兼容字形兜底、无 JD 正常出报告与有 JD 传递到各审阅节点、按缺项追问、跨轮恢复、无 Redis 恢复、账号与会话隔离、文件删除清理、新附件优先、提取版本失效、项目和经历→技能依赖、原文引用、任意 JSON 分块/转义/重复字段、首段先于综合结束、流中断不重放及 SSE 与历史一致性。完整 SDK 环境额外通过 `httpx.MockTransport` 验证真实 LangChain→DeepSeek→OpenAI SDK 的 JSON 模式、SSE 请求与响应、超时及429重试；CI 最小环境显式跳过这些 SDK 测试。

本轮后端离线回归：`LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false python3 -m pytest ai-backend/eval -q`，110项通过、2项私有 PDF 可选测试默认跳过、24项真实模型评测未执行。本地环境未安装 pytest-socket 插件；上述测试采用假模型、Mock HTTP 与临时数据库，未调用真实模型、搜索或 Redis。操作者显式指定私有 PDF 后，标题识别与阅读顺序的两组测试另行执行，18项通过（含2项私有 PDF 测试）；私有文件仅本地解析、进入临时测试数据库，未入仓库或外发。测试存在 PyMuPDF SWIG 弃用警告。本轮未改前端或部署脚本、未重新构建前端。此前最小 CI 环境与前端构建记录不作为本轮新改动的验证结果。

针对已授权的 CodeCV 样本，标题与行内代码顺序问题可显式执行本地离线回归，不把私有文件路径或完整内容写入仓库，不发送到网络。标题测试用故意漏掉目标的假模型验证程序兜底和续评链路；顺序测试验证特定行内代码与技术标签的位置。两者均不能证明真实模型的评价质量，也不是任意 PDF 的通用版面验收：

```bash
GUIDANCE_TARGET_TEST_PDF='/本地授权路径/resume.pdf' \
  python -m pytest eval/test_resume_heading.py::test_operator_pdf_heading_offline_when_explicitly_supplied \
  eval/test_pdf_reading_order.py::test_operator_pdf_inline_code_order_when_explicitly_supplied \
  -v --disable-socket --allow-unix-socket
```

真实模型评测必须显式授权，会把样本发给模型并产生费用：

```bash
python -m pytest -m llm -v
python -m pytest -m consistency -v
```

固定样本采用显式指定的“校招”测试场景，不将其作为真实候选人的意图。评测检查协议、引用、实体和有限重复稳定性，不再检查分数；它不能证明分析质量。

需要人工审核代表性案例：两年本科记录不误判、同次实习多个系统不多算、实习技能证据不忽略、常见项目不直接否定、无 JD 不编门槛，以及真实用户补充目标后能否正确续评。这部分不能仅靠假模型和自测获得可靠结论。

历史评分性能采样不代表当前指导流程，不再作为当前速度结论。付费工具级基准 `python -m eval.benchmark_scoring --live ... --position '后端开发' --application-type 校招` 可以显式指定测试目标；legacy 是不同目标的历史评分路径，不能作为同质量对照。未经授权不执行。浏览器交互、真实 Redis 延迟和真实模型质量仍需独立验收。
